# Лемана Про Челябинск — Калькулятор Грильято

Интерактивный калькулятор подвесного потолка Грильято: расчёт спецификации по формулам
Google-таблицы, онлайн-цены из листа цен, выгрузка сметы в CSV.

**Стек:** React 19 + TypeScript + Vite 7 + Tailwind CSS 4, анимации — framer-motion.
Сборка упаковывается в один файл `dist/index.html` (плагин vite-plugin-singlefile),
а картинки лежат рядом в `dist/images/`.

## 2. Проверка проекта на своём компьютере

Откройте терминал **в папке проекта** — той, где лежат `package.json`, `src/`, `index.html`.

```bash
npm ci            # установка зависимостей строго по package-lock.json
npm run build     # сборка в папку dist/
npm run preview   # локальный просмотр готовой сборки
```

Откройте в браузере адрес, который покажет `npm run preview` (обычно http://localhost:4173).
Должны быть видны:
- шапка с логотипом и жёлтая бегущая строка;
- hero-картинка с потолком на тёмном фоне;
- калькулятор с планом потолка и таблицей спецификации.

Если всё так — переходите дальше. Папку `node_modules/` и `dist/` **не загружайте на GitHub** — для них уже настроен файл `.gitignore`.

## 3. Создание репозитория на GitHub

1. Войдите на https://github.com.
2. Нажмите **+** в правом верхнем углу → **New repository**.
3. Заполните поля:
   - **Repository name** — например `grilyato-calc` (латиница, без пробелов; это войдёт в адрес сайта);
   - **Description** — необязательно, например «Калькулятор Грильято»;
   - **Visibility** — **Public**. Бесплатный GitHub Pages работает только с публичными репозиториями
     (для приватного нужен платный тариф);
   - **не отмечайте** «Add a README», «Add .gitignore», «Choose a license» — файлы уже есть в проекте.
4. Нажмите **Create repository**.
5. На открывшейся странице скопируйте адрес репозитория вида
   `https://github.com/ВАШ-НИК/grilyato-calc.git`.

> Ветку по умолчанию GitHub называет `main`. Если у вас `master`, см. раздел 11.

## 4. Загрузка проекта в репозиторий

### Способ А — через терминал (рекомендуется)

Откройте терминал в папке проекта и выполните по порядку:

```bash
git init
git add .
git status
```

Команда `git status` покажет список файлов, которые попадут в репозиторий.
**Проверьте:** в списке НЕ должно быть `node_modules/` и `dist/`, а должны быть `public/images/`,
`.github/workflows/deploy.yml`, `package-lock.json`, `src/`, `index.html`.

Если всё верно, продолжайте:

```bash
git commit -m "Калькулятор Грильято"
git branch -M main
git remote add origin https://github.com/ВАШ-НИК/grilyato-calc.git
git push -u origin main
```

**Авторизация при push.** GitHub больше не принимает пароль от аккаунта. Нужен один из вариантов:

- **Вход через браузер.** Установите [GitHub CLI](https://cli.github.com) и выполните `gh auth login`,
  выберите HTTPS и вход через браузер. После этого `git push` работает без вопросов.
- **Personal Access Token.** GitHub → **Settings** (меню профиля) → **Developer settings** →
  **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)**.
  Поставьте срок действия и галочку **repo**, нажмите **Generate token**, скопируйте токен.
  При запросе пароля в `git push` вставьте токен (символы при вставке не видны — это нормально).
  Windows сохранит его в диспетчере учётных данных.

### Способ Б — без Git, через сайт GitHub

Подходит, если терминал пугает. Минус: папки с точкой в начале имени (`.github`) браузер может пропустить,
поэтому создайте workflow вручную (шаг ниже).

1. На странице репозитория нажмите **Add file** → **Upload files**.
2. Перетащите в окно **содержимое** папки проекта, **кроме** `node_modules/` и `dist/`:
   `src/`, `public/`, `index.html`, `package.json`, `package-lock.json`, `tsconfig.json`,
   `vite.config.ts`, `README.md`, `.gitignore`.
3. Внизу в поле **Commit changes** нажмите **Commit changes**.
4. Создайте workflow вручную: **Add file** → **Create new file**, в поле имени введите
   `.github/workflows/deploy.yml` (слеши создают папки автоматически), вставьте содержимое файла
   `.github/workflows/deploy.yml` из проекта и нажмите **Commit changes**.

> При загрузке через сайт пустые папки и файлы с точкой могут потеряться. Проверьте после загрузки,
> что в репозитории есть папки `public/images` и `.github/workflows`.

## 5. Включение GitHub Pages

1. Откройте репозиторий → вкладка **Settings** (верхнее меню).
2. В левом меню найдите раздел **Code and automation** → **Pages**.

4. Больше ничего сохранять не нужно: изменение применяется сразу.

## 6. Первая публикация и проверка

Публикация запускается автоматически после загрузки кода на ветку `main` (раздел 4).
Если workflow не появился, запустите его вручную (шаг 6.2).

### 6.1. Следить за процессом

1. Откройте вкладку **Actions** репозитория.
2. Слева выберите **Deploy to GitHub Pages**, справа в списке — последний запуск.
3. Два задания:
   - **build** — установка, сборка, загрузка артефакта (около 1 минуты);
   - **deploy** — публикация (около 30 секунд).
4. Жёлтый кружок — идёт процесс, зелёная галочка — успех, красный крестик — ошибка
   (откройте задание, чтобы увидеть текст ошибки; частые случаи — в разделе 11).

### 6.2. Запустить вручную (если нужно)

Actions → **Deploy to GitHub Pages** → **Run workflow** → выберите ветку `main` → **Run workflow**.

### 6.3. Открыть сайт

Адрес сайта показан в **Settings → Pages** (блок **Visit site**). Типичный формат:

```
https://ВАШ-НИК.github.io/grilyato-calc/
```

Первый раз сайт может открываться 1–5 минут. Если видите пустую страницу или сайт без картинок,
добавьте в конце адреса косую черту `/` и обновите страницу.

### 6.4. Чек-лист после публикации

- [ ] Страница открывается, шапка и бегущая строка видны;
- [ ] hero-картинка с потолком загружается (если её нет — см. раздел 7);
- [ ] фото профиля в блоке «Система Грильято» видно;
- [ ] калькулятор считает, план потолка перерисовывается при изменении размеров;
- [ ] в спецификации есть цены (или статус «Не удалось обновить цены — показаны сохранённые»);
- [ ] кнопка «Смета CSV» скачивает файл;
- [ ] сайт открывается с телефона (адаптивная вёрстка).

## 7. Картинки на сайте: как это устроено

### Где лежат картинки

В проекте картинки хранятся в папке **`public/images/`**:

```
public/images/grilyato-hero.jpg     — фон первого экрана (потолок Грильято)
public/images/grilyato-detail.jpg   — крупный план профиля
```

При сборке Vite копирует всё из `public/` в `dist/` без изменений. Поэтому после `npm run build`
в папке `dist/` появляется `dist/images/grilyato-hero.jpg`, и GitHub Pages публикует её вместе с `index.html`.

### Почему пути в коде без слеша

В компонентах картинки подключены так:

```tsx
<img src="images/grilyato-hero.jpg" ... />
```

Адрес сайта на GitHub Pages — `…github.io/grilyato-calc/`, то есть проект живёт **в подпапке**.
Путь `/images/...` (со слешем) указывал бы в корень домена `github.io` и картинка не нашлась бы.
Путь `images/...` (без слеша) браузер строит относительно текущего адреса, и всё работает.

> Поэтому адрес сайта должен заканчиваться на `/` (см. раздел 6.3). Ссылка без него тоже обычно
> перенаправляется, но на всякий случай используйте адрес с косой чертой.

### Как добавить новую картинку

1. Положите файл в `public/images/`, например `public/images/banner.webp`.
2. В коде укажите путь **без слеша**: `<img src="images/banner.webp" alt="Описание" />`.
3. Проверьте локально: `npm run build`, затем в `dist/images/` должен появиться файл.
4. Загрузите изменения (раздел 8).

### Рекомендации по картинкам

- **Размер файла** — до 300–500 КБ. GitHub не принимает файлы больше 100 МБ, а больше 50 МБ предупреждает.
  Большие фото сожмите на https://squoosh.app.
- **Формат** — `.jpg` для фото, `.webp` или `.png` для графики с прозрачностью.
- **Имена** — только латиница, цифры, дефисы: `grilyato-hero.jpg`, а не `Грильято фон.jpg`.
  Кириллица и пробелы в именах иногда ломают ссылки.
- **Регистр важен.** `Hero.jpg` и `hero.jpg` — разные файлы для GitHub (Linux), хотя на Windows
  и macOS они открываются одинаково. Имя в коде должно совпадать с именем файла точно.
- **Не добавляйте** картинки в `.gitignore`: папка `public/` и файлы `.jpg` должны быть в репозитории.

### Если картинка не видна на сайте

Откройте сайт, нажмите F12 → вкладка **Network** (или **Сеть**) → обновите страницу → найдите
строку с именем картинки. Статус:
- **404** — файл не найден: проверьте имя и регистр в коде и наличие файла в `public/images/`;
- **200** — файл загружен, проблема в вёрстке или в CSS;
- картинки нет в списке — код ссылается на другой путь.

## 8. Обновление сайта после правок

После любых изменений кода или картинок:

```bash
git add .
git commit -m "Что изменилось, например: обновлена hero-картинка"
git push
```

GitHub Actions сам соберёт проект и опубликует новую версию. Прогресс — во вкладке **Actions**.
Обычно изменения видны через 1–3 минуты. Чтобы увидеть их сразу, обновите страницу с очисткой кэша
(Ctrl+F5 или Cmd+Shift+R).

**Важно:** всегда проверяйте `git status` перед `git add .` — не должно появиться `node_modules/` или `dist/`.
Эти папки уже в `.gitignore`, поэтому обычно они не попадают в список.

## 9. Google-таблица с ценами

Цены подгружаются из листа Google-таблицы при открытии сайта и обновляются каждые 60 секунд.
Чтобы цены работали на опубликованном сайте:

1. Откройте таблицу → **Настройки доступа** (кнопка «Открыть доступ» / «Share»).
2. Выберите **Все, у кого есть ссылка** → роль **Читатель**.
3. Проверьте в браузере адрес выгрузки листа цен — должен открыться CSV с колонками
   «Артикул», «Цена», «Ссылка на товар»:
   `https://docs.google.com/spreadsheets/d/ID_ТАБЛИЦЫ/gviz/tq?tqx=out:csv&gid=84984568`

Если таблица недоступна, калькулятор не ломается: он показывает сохранённые цены и жёлтую
плашку «Не удалось обновить цены». Изменить цену можно, отредактировав столбец **B** листа.

## 10. Собственный домен

Если у вас есть домен (например `grilyato.example.ru`):

1. **Settings → Pages → Custom domain** → введите домен → **Save**.
   GitHub создаст файл `CNAME` в ветке сборки (для нашего workflow это не требуется — при необходимости
   добавьте файл `public/CNAME` с одной строкой — вашим доменом, тогда он попадёт в `dist/`).
2. У регистратора домена создайте DNS-запись:
   - для поддомена (`www.example.ru` или `calc.example.ru`) — **CNAME** → `ВАШ-НИК.github.io`;
   - для корневого домена (`example.ru`) — четыре записи **A** на IP GitHub:
     `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`.
3. Подождите распространения DNS (от 10 минут до суток).
4. Вернитесь в **Settings → Pages**, дождитесь проверки DNS и включите **Enforce HTTPS**.

> С собственным доменом адрес сайта становится корневым (`https://grilyato.example.ru/`),
> поэтому пути к картинкам без слеша тоже работают.

## 11. Решение проблем

| Симптом | Причина | Решение |
|---|---|---|
| В Actions красный крестик на шаге **Deploy** с текстом про Pages / Pages not enabled | Не выбран источник Pages | Settings → Pages → Source → **GitHub Actions**, затем Re-run jobs |
| Workflow вообще не запускается | Файл не в той папке или не на той ветке | Путь должен быть `.github/workflows/deploy.yml`, ветка — `main` |
| Ветка называется `master`, а не `main` | В workflow указана `main` | Переименуйте: `git branch -M main && git push -u origin main`, либо в `deploy.yml` в блоке `branches` замените `main` на `master` |
| Шаг **Install** / `npm ci` падает | Нет `package-lock.json` в репозитории | Добавьте файл и загрузите: `git add package-lock.json && git commit -m "lock" && git push` |
| Сборка падает с ошибкой TypeScript | Локально не проверяли | Выполните `npm run build` у себя и исправьте ошибку до `push` |
| Сайт открывается, но пустой / белый экран | Открыт адрес без `/` или кэш браузера | Добавьте `/` в конец адреса, Ctrl+F5 |
| Картинки не видны | Неверный путь, регистр в имени или файл не в `public/images/` | См. раздел 7 → «Если картинка не видна» |
| Ошибка `Get Pages site failed` / `Resource not accessible by integration` | Pages не включён или нет прав | Включите Pages (раздел 5); Settings → Actions → General → Workflow permissions → **Read and write permissions** |
| Ошибка `Pages site is not available for private repos` | Репозиторий приватный на бесплатном тарифе | Сделайте репозиторий **Public** (Settings → General → Danger Zone → Change visibility) |
| Цены не загружаются, в спецификации «Не удалось обновить» | Таблица закрыта для доступа по ссылке | Раздел 9 |
| Ссылка Google-таблицы не открывается с сайта | Таблица удалена или переименован лист / gid | Проверьте ссылку и gid листа с ценами |
| `git push` просит пароль и не принимает его | Пароль больше не поддерживается | Используйте Personal Access Token или `gh auth login` (раздел 4) |
| `git push` пишет `rejected (fetch first)` | На GitHub уже есть коммиты, которых нет у вас | Создавали репозиторий с README? Выполните `git pull origin main --allow-unrelated-histories`, затем `git push` |
| Папка `node_modules` попала в коммит | Не было `.gitignore` при первом `git add` | `git rm -r --cached node_modules`, затем коммит |

## 13. Альтернатива: публикация без Actions

Этот способ проще для понимания, но сборку нужно делать вручную перед каждой публикацией.
Папка `dist/` в `.gitignore`, поэтому её нельзя отправить обычным `git push` — используем утилиту `gh-pages`.
Она загружает содержимое `dist/` (включая `images/`) в отдельную ветку `gh-pages`.

```bash
npm run build
npx gh-pages -d dist
```

Первый запуск `npx` попросит подтвердить установку пакета `gh-pages` — ответьте `y`.
Пакет ставится во временный кэш и не добавляется в `package.json`.

Затем один раз включите публикацию из ветки:
**Settings → Pages → Source → Deploy from a branch → Branch: gh-pages, папка / (root) → Save**.

Чтобы обновить сайт, повторите `npm run build` и `npx gh-pages -d dist`.

> Если в **Settings → Pages** уже выбран источник **GitHub Actions**, переключите его на
> **Deploy from a branch**, иначе Actions продолжит публиковать сайт и перезапишет ваши изменения.
